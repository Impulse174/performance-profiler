## ✨ Возможности

### Основное
- 📊 **Профилирование функций** - анализ любых функций из стандартной библиотеки и пользовательских модулей
- 📁 **Профилирование скриптов** - запуск и анализ целых Python файлов
- ⚡ **Async поддержка** - корректная работа с асинхронными функциями
- 🧠 **Умный парсинг** - автоматическое определение типов аргументов (int, float, bool, JSON)

### Метрики производительности
- 🕐 **Время выполнения** - реальное (wall-clock) и процессорное время
- 💾 **Использование памяти** - до/после, пиковое потребление
- 🗑️ **GC статистика** - отслеживание сборщика мусора
- 📦 **Размер результата** - точное измерение памяти возвращаемого значения

### Продвинутые функции
- 🔍 **Анализ алгоритмической сложности** - автоматическое определение O-нотации через AST
- ⚙️ **Гибкая конфигурация** - централизованное управление настройками
- 📝 **Декораторы** - простое добавление профилирования через @auto_profile
- 🎯 **Детальное логирование** - настраиваемый уровень и формат вывода

## 📦 Установка

### Быстрая установка


## Использование

### Профилирование функций

```bash
python profile_cli.py module_name function_name [args...] [--kwargs '{"key": "value"}']
```

#### Примеры:

```bash
# Профилирование стандартной функции
python profile_cli.py math factorial 10

# Профилирование функции с JSON аргументом - просто вызывает стандартную функцию сериализации JSON с указанными аргументами и замеряет её производительность.
python profile_cli.py json dumps '{"number": 42, "text": "hello"}'

# Профилирование функции с именованными аргументами
python profile_cli.py json dumps "[1, 2, 3]" --kwargs '{"indent": 2}'

# Профилирование функции из вашего модуля
python profile_cli.py my_module my_function "arg1" 42 true
```

### Профилирование файлов

```bash
python profile_cli.py --file test_module.py
```

#### Примеры:

```bash

python profile_cli.py --file my_script.py

# Профилирование файла с относительным путем
python profile_cli.py --file ../other_project/script.py

# Профилирование файла с абсолютным путем
python profile_cli.py --file D:\Programming\project2\app.py
python profile_cli.py --file /home/user/project/script.py
```

## Типы аргументов

Инструмент автоматически определяет и преобразует типы аргументов:

- **Числа**: `10`, `3.14` → int/float
- **Строки**: `"hello"` → str
- **Булевы значения**: `true`, `false` → bool
- **JSON объекты**: `'{"key": "value"}'` → dict/list
- **Всё остальное**: остается строками

## Статистика профилирования

Для каждого профилирования выводится подробная статистика:

🕐 Время выполнения (execution time)

Описание: Общее реальное время, прошедшее от вызова функции или запуска скрипта до его завершения. Включает все задержки: ожидание I/O, блокировки, переключения потоков, а также время работы CPU.
Измерение: Секундомерное отслеживание — time.time() в Python или аналогичные таймеры на других языках.
Единицы: секунды (с), дробные значения с высокой точностью.
Особенности:
Включает время ожидания сетевых запросов, операций с диском и блокировок потоков.
Хорошо для оценки "пользовательского опыта" или общей производительности программы.
Пример: 0.215818 с — функция завершилась примерно за 0.216 секунды реального времени.

🖥️ CPU time

Описание: Время, в течение которого процессор реально выполнял код функции/скрипта. Не учитывает периоды ожидания (sleep, I/O, блокировки).
Измерение: time.process_time() в Python, измеряет только активный процессорный ресурс.
Единицы: секунды (с).
Особенности:
CPU time ≥ execution time при однопоточном коде редко; обычно CPU time ≤ execution time.
Полезно для выявления "тяжелых" операций по нагрузке на процессор.
Пример: 0.218750 с — процессор работал над кодом примерно 0.219 секунды.

💾 Память (до/после)

Описание: Измеряет текущий объем оперативной памяти, занимаемой процессом до и после выполнения.
Измерение: psutil.Process().memory_info().rss или аналогичные средства.
Единицы: мегабайты (МБ).
Особенности:
Помогает понять, сколько памяти "добавляется" при вызове функции.
Важно учитывать возможное кэширование объектов Python и внутренние структуры.
Формат: память_до / память_после.
Пример: 23.00 / 23.55 МБ — функция увеличила потребление памяти на 0.55 МБ.

📈 Пиковая память

Описание: Максимальное потребление памяти процессом во время выполнения функции/скрипта.
Измерение: tracemalloc.get_traced_memory() в Python или внешние профайлеры (memory_profiler).
Единицы: мегабайты (МБ).
Особенности:
Пиковая память ≠ память после выполнения, так как сборщик мусора может освободить часть ресурсов.
Полезно для анализа "взрывного" роста памяти при больших данных.
Пример: 1.11 МБ — пиковое потребление 1.11 МБ.

🗑️ Изменение GC count

Описание: Изменение количества объектов, отслеживаемых сборщиком мусора Python.
Измерение: gc.get_count() до и после выполнения; разница показывает, сколько объектов было создано и/или очищено.
Единицы: количество объектов.
Особенности:
Полезно для обнаружения утечек памяти.
Не показывает точное количество удалённых объектов, а разницу между текущими счетчиками поколений.
Пример: 14 — увеличение на 14 объектов в текущих поколениях GC.

📦 Размер результата

Описание: Объем памяти, который занимает результат выполнения функции или скрипта.
Измерение: sys.getsizeof(result) для базовых объектов или pympler.asizeof для рекурсивного подсчёта всех вложенных объектов.
Единицы: байты (B).
Особенности:
Полезно для анализа, особенно если функция возвращает большие структуры данных (списки, словари, массивы numpy).
Иногда реальный объем памяти может быть больше из-за ссылок на другие объекты.
Пример: 202252 байт — размер результата ~197 КБ.

## Автоматическое профилирование функций

### Вариант 1: Явное использование декоратора

Добавьте декоратор `@auto_profile` над каждой функцией которую хотите профилировать:

```python
# my_functions.py
from auto_profile import auto_profile

@auto_profile
def heavy_calculation(n):
    return sum(i**2 for i in range(n))

@auto_profile
def process_data(data):
    return [x * 2 for x in data]

# При вызове этих функций автоматически будет выведена статистика
result = heavy_calculation(1000000)
```

### Вариант 2: Автоматическое профилирование всего модуля

Просто импортируйте `auto_profile` один раз в начале файла - все функции будут профилироваться автоматически:

```python
# my_module.py
import auto_profile  # Все функции в этом файле будут профилироваться

def function1():
    # Эта функция будет профилироваться
    pass

def function2():
    # Эта тоже
    pass
```

### Запуск профилирования

Просто запустите ваш Python файл обычным способом:

```bash
python my_functions.py
python 1.py
python demo.py
```

## Создание своих модулей для профилирования

Чтобы профилировать свои функции, создайте Python файл:

```python
# my_module.py
def my_function(a, b, c="default"):
    """Пример функции для профилирования"""
    result = a + b
    if c != "default":
        result *= 2
    return f"Результат: {result}, c={c}"

# Для профилирования:
# python profile_cli.py my_module my_function 10 20 --kwargs '{"c": "custom"}'
```

## Анализ алгоритмической сложности

Инструмент позволяет анализировать временную и пространственную сложность алгоритмов через профилирование производительности.

### Примеры сложности

#### O(n) - Линейная сложность
```python
# Пример: линейный поиск
@auto_profile
def linear_search(arr, target):
    """Линейный поиск - O(n) временная сложность"""
    for i, element in enumerate(arr):
        if element == target:
            return i
    return -1

# Результаты профилирования:
# Время выполнения: ~0.27 секунды для 1 млн элементов
# CPU время: ~0.28 секунды
# Память: O(1) - константная дополнительная память
```

#### O(1) - Константная сложность
```python
# Пример: доступ к элементу массива
@auto_profile
def get_element(arr, index):
    """Доступ к элементу - O(1) временная сложность"""
    return arr[index]
```

#### O(log n) - Логарифмическая сложность
```python
# Пример: бинарный поиск
@auto_profile
def binary_search(arr, target):
    """Бинарный поиск - O(log n) временная сложность"""
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

#### O(n²) - Квадратичная сложность
```python
# Пример: пузырьковая сортировка
@auto_profile
def bubble_sort(arr):
    """Пузырьковая сортировка - O(n²) временная сложность"""
    n = len(arr)
    for i in range(n):
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
    return arr
```

### Как определить сложность через профилирование

1. **Замерьте время выполнения** для разных размеров входных данных
2. **Проанализируйте зависимость** времени от размера данных
3. **Сравните с теоретическими значениями**:
   - O(1): время не меняется
   - O(log n): время растет медленно
   - O(n): время растет линейно
   - O(n log n): время растет быстрее линейного
   - O(n²): время растет квадратично

### Практический пример

```bash
# Профилирование линейного поиска
python 1.py

# Результаты показывают O(n) сложность:
# - Время ~0.27с для n=1,000,000
# - Линейная зависимость времени от размера данных
# - Константная память O(1)
```
